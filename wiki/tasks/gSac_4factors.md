# gSac_4factors

On every trial the subject fixates a central point. One target flashes at one
of four peripheral locations, and the subject keeps fixating through a short
delay. When the fixation point turns off (the go signal), the subject saccades
to the remembered location and holds gaze there for reward. The task crosses
four factors: **stimulus identity/salience** (face image, non-face image, or a
DKL-colour bullseye at high or low salience), **reward magnitude** (high/low by
hemifield, swapped every half-block), **location probability** (one
high-probability location per block), and **target location** (4 locations).
The neural question is how these factors modulate saccade-related activity at
the recorded RF. It is the most developed member of the
[gSac family](family-gsac.md) and is used for current recordings.

The full behavioural description is
[`analysisPlanningDocs/gSac_4factors_task_description.md`](../../analysisPlanningDocs/gSac_4factors_task_description.md).
The design spec is `tasks/gSac_4factors/gSac_4factors_task_design_specification.md`.
This page summarises both and points to the code.

## Trial flow

The state machine is `stateMachine` in `gSac_4factors_run.m`. `timingMachine`
switches the target on and off, and `drawMachine` draws and flips (see
[run-loop state machine](../concepts/run-loop-state-machine.md)). All times are
drawn once per trial in `nextParams.m → timingInfo`, relative to fixation
acquisition (`fixAq`):

1. `trialBegun` → `waitForJoy`: the `trialBegin` code is strobed. `pds.joyHeld` returns true immediately when `passJoy = 1` (see Session practice).
2. `showFix`: the fixation point (black square outline) appears. Gaze must enter the fixation window within `fixWaitDur` (3 s), or the trial ends as `nonStart`.
3. `dontMove`: hold fixation. The target turns on at `timeTargOnset` = U(`targOnsetMin`, `targOnsetMax`) = U(0.75, 1.0) s and off after `targetFlashDuration` (0.4 s). The go signal is at `timeFixOffset = timeTargOnset + U(goTimePostTargMin, goTimePostTargMax)` = +U(0.5, 1.0) s, so it comes 100–600 ms after the target turns off. `isVisSac` is always 0.
4. `makeSaccade`: the fixation point is extinguished. Leaving the window before `goLatencyMin` (0.1 s) or making no saccade by `goLatencyMax` (1.0 s) gives `fixBreak`. Onset requires gaze outside the window **and** online velocity > `eyeVelThresh` (100 °/s, `gazeVelThreshCheck`). The late-saccade check runs only once `timing.fixOff > 0` (the [postFlip rule](../concepts/drawing-and-postflip.md)).
5. `checkLanding`: wait while velocity stays above threshold. Then a blink check (any sample > 35° since `fixOff` → `blinkDuringSac` strobe, `fixBreak`), then the target-window check.
6. `holdTarg`: the target reappears (`targetReillum`) as confirmation, and gaze must stay in the window for U(0.2, 0.3) s.
7. `sacComplete`: `pds.deliverReward` with `rewardDurationMs`. The trial continues for the reward duration + DAC pad + `postRewardDuration` (0.25 s).

Error states (`fixBreak`, `joyBreak`, `nonStart`) play a low tone and end the
trial. `postTrialTimeOut` uses a zero timeout for every end state. Visual
events (`fixOn`, `fixOff`, `targetOn`, `targetOff`, `targetReillum`) are
queued with `addValue`/`addValueOnce`, strobed after the flip, and timestamped
via `p.trVars.postFlip`. Behavioural events go through `strobeNow`.

## Conditions / trial structure

`initTrialStructure.m → fourFactorsTable` builds a recipe table with one row
per half-block × location × stimType. The columns are `halfBlock`,
`targetLocIdx`, `stimType`, `salience`, `reward`, `targetColor`, `numTrials`,
`trialCode`. The table is expanded into `p.init.trialsArray` and shuffled
within each block (see [trial structure](../concepts/trial-structure.md)).

- **stimType 1–6:** 1 face, 2 non-face (image trials, `salience = 0`, `targetColor = 0`); 3/4 bullseye high/low salience at hue A (0° DKL); 5/6 high/low salience at hue B (180° DKL).
- **Blocks:** 4 half-blocks make 2 blocks. Location 1 is high-probability in block 1, location 3 in block 2.
- **Reward:** locations 1–2 (hemifield A) are high-reward in half-blocks 1 and 3, and locations 3–4 in half-blocks 2 and 4.
- **Counts per half-block:** a bullseye code gets 5 reps at the high-probability location and 1 at each low-probability location. Image codes get double reps (10/2), which balances image and bullseye trials 32/32. A half-block is 64 correct trials and a full cycle is 256 (since 2026-10-18, a9564f6b; sessions before that used 48/192, see the change history).
- **trialCode** = `26000 + 1000·block + (targetLocIdx−1)·6 + stimType`, giving 27001–27024 and 28001–28024. It does not encode half-block or reward.

`nextParams.m → chooseRow` draws a random available row from the
lowest-numbered half-block that still has rows. `updateTrialsList` marks a row
done only after a correct trial, so errored conditions are redrawn later in the
same half-block. Once every row is done, `updateTrialsList` resets the pool and
selection starts again at half-block 1.

**Locations** (`nextParams.m → setLocations`): the base
(`targDegX_base`, `targDegY_base`, default 17, 3) is rotated in 90° steps. The
step is −90° when x and y share a sign and +90° otherwise, which keeps
locations 1–2 in the same left/right hemifield as the base.

**Stimuli and colour.** Images come from `stimuli/gSac_4factors/images.mat`.
`initImageTextures` loads rows 1–15 as faces and rows 31–150 as non-faces,
remaps their pixels onto the CLUT grayscale ramp (indices 18–255), and makes
them 6° indexed textures (`p.stim.stimDiamDeg`). Bullseyes are two square
frames (`outerRingDeg` 4°, `innerRingDeg` 2°, `targWidth` 12 px).
`initClut` builds a dual CLUT from DKL hues 0/45/180/225 and isoluminant
grey (`mean_lum = -0.495`, `satRad = 0.4`, per-rig `LUT_VPIXX_rig<N>` via
`initmon`). `nextParams → updateTrialClut` sets the trial background:

| stimType | background | target |
|---|---|---|
| 1, 2 | grey | image |
| 3 | 180° DKL | 0° (high salience) |
| 4 | 45° | 0° (low) |
| 5 | 0° | 180° (high) |
| 6 | 225° | 180° (low) |

The background shows from the first frame, so it signals category and (for
bullseyes) salience/hue before target onset (task description §4.3). A green
frame on the experimenter display marks high-reward trials. See
[colour and calibration](../concepts/color-and-calibration.md) and the
salience table in `CLAUDE.md`.

## Key trVars and settings

There is a single settings file. These GUI variables (`p.rig.guiVars`) matter
for sessions:
`targDegX_base`/`targDegY_base` (location 1), `rewardDurationHigh` (350 ms) and
`rewardDurationLow` (160 ms), `targWinWidthDeg`/`targWinHeightDeg` (8, which are
half-widths, giving a ±8° window), `targTrainingDelay` (−1 = off; ≥0 turns the
target back on that long after the go signal), and `passEye`.
`p.init.exptType = 'gSac_4factors'` selects the recipe. `wantOnlinePlots`
(false) controls the gaze-trace plots. `updateOnlinePlots` always updates the
per-factor peak-velocity/RT/endpoint-error metrics after correct trials (see
[online plotting](../concepts/online-plotting.md)).

Task actions include `dklToRgbFileMaker`, `i1CalibrateAndMeasure` and
`i1Validate` (in `tasks/gSac_4factors/actions/`) for i1 photometer
calibration (see [actions](../library/pdsActions.md)).

## Data & strobes

`gSac_4factors_finish.m` handles the end of each trial. It reads the DataPixx
buffers, strobes `p.init.strobeList` via `pds.strobeTrialData`, then
`trialEnd`. It pulls Ripple spikes/events if connected (`pds.getRippleData`)
and computes `preSacXY`, `postSacXY`, `peakVel` and `SRT` in `calcSacParams`.
That function uses a 29-tap smoothed differentiator and `eyeVelThreshOffline`
(100 °/s), and the SRT is trial-relative onset − `fixOff`, NaN on error trials.
Finally it calls `pds.saveP` (see [data saving](../concepts/data-saving.md)).
Per trial, `p.trVars` holds the condition (`halfBlock`, `targetLocIdx`,
`stimType`, `salience`, `reward`, `targetColor`, `trialCode`, `imageIdx`,
`rewardDurationMs`, `targDegX/Y`, timing draws), plus a copy of `p.stim` in
`p.trVars.stim`. `imageIdx` is the row in `images.mat` of the image shown, and
0 on bullseye trials.

The generated table above lists the end-of-trial strobes. Location is strobed
as polar `targetTheta` (angle × 10) and `targetRadius` (ecc × 100), plus
`targetLocIdx`. `imageId` (code 6660) carries `imageIdx`. Event codes and the
reward-level caveat are summarised in task description §9. See also
[strobe codes](../concepts/strobe-codes.md) and the
[registry](../reference/strobe-codes.md).

Field definitions are in
[`data_dictionaries/4factors_data_dictionary.md`](../../data_dictionaries/4factors_data_dictionary.md).
`imageIdx`/`imageId` (added 2026-10-15) is not yet listed there or in the task
description's strobe summary. Analysis plan:
`analysisPlanningDocs/gSac_4factors_analysis_planning.md`.

## Session practice & decisions

- **Location 1 is placed on the RF** (per the user, 2026-10-02). The base location (`targDegX_base`/`targDegY_base`) is set on the recorded neurons' receptive field. Placing it opposite the RF instead is how block/reward order is counterbalanced across sessions. In that case the RF location becomes location 3, which is high-probability in block 2 and starts low-reward.
- **`passJoy = 1` always** (per the user, 2026-10-02). The monkeys no longer press the joystick. The joystick option is kept in the code deliberately, and setting `passJoy = 0` makes it required again. `p.trVars.passJoy` in the saved data records which setting applied.
- The go-signal window was set so the memory delay after target offset is 100–600 ms, matching the older gSac tasks with the longer 0.4 s flash (commit 19c9e3a5 message).
- **Image and bullseye trials are balanced from 2026-10-18 on** (per the user, 2026-10-18). Image codes get double reps so the two categories are equal in number, while the bullseye hue counterbalancing and the 5:1 probability ratio are preserved (comment in `fourFactorsTable`; design spec §6.4). Earlier sessions used equal reps per stimulus code (bullseye:image 2:1); the user chose balanced categories for future sessions, knowing it changes the design mid-dataset and lengthens each half-block from 48 to 64 correct trials. Neither version confounds stimulus type with reward, probability or location; they differ in which groupings are equally frequent.

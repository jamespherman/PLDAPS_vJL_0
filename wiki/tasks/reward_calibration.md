# reward_calibration

A utility task with no subject behavior. Each "trial" delivers one reward pulse of
`rewardDurationMs` through `pds.deliverReward`. After `numTrials` pulses (default 100),
`_finish` sets the GUI's Run button (`Tag 'runButton'`) to false, which stops the loop
([reward](../concepts/reward.md)).

## Trial flow

`reward_calibration_run.m` has one active state, `trialBegun`. It strobes `trialBegin`,
calls `pds.deliverReward`, and exits the loop (strobing `trialEnd` on exit). `drawMachine` is empty, so nothing is drawn.
`_finish` strobes `trialEnd` again, saves `p` (`pds.saveP`), and pauses 0.5 s before the next
pulse. The other states in the generated block are defined in the settings file but never entered.

## Conditions / trial structure

None. `reward_calibration_init.m` does not call `initTrialStructure`, and
`reward_calibration_next.m` only increments the trial counter, copies `trVarsGuiComm` to
`trVars`, sets the DataPixx schedules, and resets `trData`. The `supportFunctions/` folder
still holds scd-derived files (for example `nextParams.m` with scd's `chooseRow`) that
this task does not call; see the [family page](family-scd.md#shared-ancestry).

## Key trVars

The GUI exposes `rewardDurationMs` (default 280) and `numTrials` (default 100); the other
GUI entries are left over from scd. The rig config is chosen from the hostname
(`rigConfig_rig<N>`). `initClut` loads the `LUTvpixx` monitor files.

## Data & strobes

Only `trialBegin`, `reward` (from `pds.deliverReward`) and `trialEnd` are strobed. The
strobeList holds the session date and time, but `_finish` does not call
`pds.strobeTrialData`. Each trial file records the reward timing and the strobed list.

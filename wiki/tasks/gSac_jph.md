# gSac_jph

gSac_jph is a guided-saccade task used for **saccade/RF mapping**. The subject
fixates, a square target appears in the periphery, and the subject saccades to
it when the fixation point turns off. The target either stays on (visually
guided) or flashes (memory guided). Target locations are supplied
trial by trial by the **saccade mapping GUI** (`saccadeGUI.m`). The GUI plots
saccade metrics and Ripple spike counts per target location, so response
fields can be mapped online. Shared design and the comparison with the
other gSac tasks are on the [family page](family-gsac.md).

## Trial flow

The states are the shared gSac set (see the generated list).
`gSac_jph_run.m` added these to [gSac](gSac.md):

- `onlineGazeCalcs` stores `[x, y, t, velocity]` per loop in `p.trData.onlineGaze`. Saccade onset in `makeSaccade` requires leaving the fixation window within `goLatencyMin`–`goLatencyMax` (0.1–1 s) **and** velocity > `eyeVelThresh` (`gazeVelThreshCheck`).
- `checkLanding` waits until velocity drops. Any gaze sample since `fixOff` with |x| or |y| > 35° counts as a blink (`blinkDuringSac`, `fixBreak`). Otherwise landing must be inside the target window.
- On memory trials the target is re-illuminated in `holdTarg`, or `targTrainingDelay` s after the go signal when that is ≥ 0.
- Event times (`fixOn`, `fixOff`, `targetOn`, …) are recorded as `timeNow` in the state and timing machines. Visual event codes are queued and strobed after the flip.

## Conditions / target selection

`setTargLocViaGui = true` by default. `extraWindowSetup` then opens
`saccadeGUI(false)` next to the main PLDAPS GUI and stores its handle object in
`p.rig.guiData`. In `nextParams.m → setLocations`:

- If the GUI's **specified** button is selected, the target goes to the GUI's X/Y fields.
- Otherwise the next unvisited row of `p.rig.guiData.sacDataArray` is used. `saccadeGUI → initTargetLocs` initially tiles a grid in random order.
- Once every location has been visited, the target is drawn at a random angle with a radius inside a rectangular annulus (`getRadius`, using `minTargAmp`, `maxHorzTargAmp`, `maxVertTargAmp`).

The alternatives are mouse placement (`setTargLocViaMouse`), a trial array
(`initTrialStructure.m`: `all_locs`/`two_locs` give 6 elevations at
`staticTargAmp`), and the ring/grid list from `initTargetLocationList`
(`targLocationPreset = 'nRing'`). `propVis = 1`, so trials are visually guided
by default. Lowering it mixes in memory trials (`targetFlashDuration` 0.2 s).

## Key trVars

The GUI-exposed variables include `rippleChanSelect` (spikes from this unit
are sent to the GUI; 0 = all), `propVis`, `targWinWidthDeg`/`HeightDeg`,
`passEye` and `passJoy`. `wantOnlinePlots = true` makes `updateOnlinePlots`
draw gaze/velocity traces after correct trials (see
[online plotting](../concepts/online-plotting.md)). Colours come from a
dual CLUT (`initClut`, per-rig `LUT_VPIXX_rig<N>` files via `initmon`).

## Data & strobes

`gSac_jph_finish.m` strobes the strobeList (see the generated table) and
`trialEnd`. It fetches Ripple data if `p.rig.ripple.status`, computes
`preSacXY`/`postSacXY`/`peakVel`/`SRT` in `calcSacParams`, and saves with
`pds.saveP`. After a correct trial, `postTrialGui` writes the saccade
metrics into `sacDataArray` and appends that trial's spike/event times to
`p.rig.guiData.spikesAndEvents`. These handle-object properties drive the
GUI's heat maps and spike plots. The GUI receives only `p.init` and
`p.rig.ripple` (in `p.rig.guiData.pldapsData.p`). The GUI can save its figure
and a `.mat` of its map data independently of PLDAPS output.

Field definitions are in
[`data_dictionaries/gSac_jph_data_dictionary.md`](../../data_dictionaries/gSac_jph_data_dictionary.md),
and the analysis plan is in `analysisPlanningDocs/gSac_jph_analysis_planning.md`. Location is
strobed as `targetTheta`/`targetRadius`, and there is no `trialCode` (see
[strobe codes](../concepts/strobe-codes.md)).

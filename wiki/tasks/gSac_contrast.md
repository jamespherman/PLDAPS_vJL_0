# gSac_contrast

gSac_contrast is a memory-guided saccade task (`propVis = 0`) in which
**target salience** and **reward magnitude** vary. The target is a square
outline whose DKL hue sits either 180° (high salience) or 45° (low salience)
from the hue of the full-screen background. The target appears at one of two
diametrically opposed locations. It was added 2024-06-06 (ac709aa8), and
[gSac_4factors](gSac_4factors.md) began as a copy of it. Shared mechanics and
the comparison table are on the [family page](family-gsac.md).

## Trial flow

The state machine matches [gSac_jph](gSac_jph.md): velocity-threshold saccade
onset, blink check, target re-illumination in `holdTarg`, and event times
taken as `timeNow`. The fixation point is black. `nextParams.m → timingInfo`
draws timing from `p.trVarsInit` values: target onset U(0.75, 1.0) s after
`fixAq`, a 0.2 s flash, and go at onset + U(0.3, 0.8) s. On high-reward
trials (`p.trVars.rwdSize == 1`) the experimenter display shows an extra frame
at 1.1× the target window.

## Conditions / trial structure

`initTrialStructure.m → rwdSaliencyTable` defines 32 rows: `targetLocIdx`
(1, 2) × `tgtBkgndCond` (1–8) × `highLowRwd` (1 high, 2 low), with 3 reps
each (96-trial block). The trial codes are 24001–24032. `nextParams.m → trialTypeInfo`
maps `tgtBkgndCond` to target/background DKL hues, and `redefClut` uploads a
CLUT whose background entries take the trial's background colour.

| tgtBkgndCond | target / background | salience |
|---|---|---|
| 1, 2 | 0°/180°, 180°/0° | high |
| 3, 4 | 90°/270°, 270°/90° | high |
| 5–8 | 0°/45°, 90°/135°, 180°/225°, 270°/315° | low |

`initClut` defines the DKL hues 0:45:360 at `satRad = 0.4`. Each hue has its
own luminance value (`dklLum`), which the code comment describes as
empirically chosen to keep measured target/background luminance within 0.4%.

**Locations:** location 1 is `targDegX/Y` (default −6, 0) or the
saccadeGUI-specified point if that GUI is open with its "specified" button selected. Location 2 is its negation.

**Selection** (`chooseRow`): each block is drawn in two phases by the
location–reward pairing in `p.status.tLoc1HighRwdFirst`. Rows with location 1
low-reward and location 2 high-reward come first, or the opposite pairing,
and the remaining rows follow. `updateTrialsList` flips the flag when a block
completes. After an error trial `chooseRow` keeps the same row, so aborted
trials repeat immediately (d9bf98cc).

## Key trVars

`rewardDurationHigh` is 350 ms and `rewardDurationLow` 160 ms. GUI variables
include `targDegX`, `targDegY`, `propVis`, `targTrainingDelay` and `rewardDurationHigh`/`rewardDurationLow`. Task actions
`dklToRgbFileMaker`, `i1CalibrateAndMeasure` and `i1Validate`
(`tasks/gSac_contrast/actions/`) handle photometer calibration (see
[colour and calibration](../concepts/color-and-calibration.md)).

## Data & strobes

`gSac_contrast_finish.m` follows gSac_jph: strobeList, Ripple fetch when
`recChans` is non-empty, `calcSacParams`, `pds.saveP`, and `postTrialGui` only
if `p.rig.guiData` exists. The trial's condition is identified by the strobed
`trialCode`. `p.trVars.stimConfigIdx` and `p.trVars.rwdSize` are saved per
trial. There is no separate data dictionary. The analysis outline is in
`analysisPlanningDocs/gSac_contrast_analysis_planning.md`.

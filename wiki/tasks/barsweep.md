# barsweep

The subject fixates while a single bar moves across the screen along a straight path, one
sweep per trial. Holding fixation through the whole sweep earns a reward. Spikes from
Ripple are binned against the bar's position to build an online per-channel RF estimate.
The task is a port of collaborator code (`feng_LGN`) into PLDAPS conventions
(`analysisPlanningDocs/barsweep_implementation_plan.md`). Two regimes share one quintet
and differ only in angle list, strobes and reconstruction:

| Regime (`p.init.exptType`) | Settings file | Directions | Online reconstruction |
|---|---|---|---|
| `barsweep_cardinal4` | `barsweep_cardinal4_settings.m` | `[0 90 180 270]` | per-direction PSTH peaks; azimuth = midpoint(0°, 180°), elevation = midpoint(90°, 270°); latency from peak separation |
| `barsweep_rfmap12` | `barsweep_rfmap12_settings.m` | `0:30:330` | 2-D filtered back-projection via `iradon` over 6 orientations |

`barsweep_rfmap12_settings.m` is a thin wrapper. It calls the cardinal4 file, changes
`exptType`, appends two strobes (`barsweepRfRampCutoff_x100`, `barsweepRfRampFilter`)
and sets the `barsweepExptType` strobe value to `2`.

## Trial flow

`trialBegun → showFix → holdFixAndSweep → trialComplete` (rewarded), with aborts to
`fixBreak` and `nonStart` (see the generated state list). In `holdFixAndSweep` the
fixation-break check runs **before** the completion check, so reward is reachable only if
gaze stayed in the window on every bar frame. After the last bar frame, `stimOff` and
`fixOff` are tagged via [postFlip](../concepts/drawing-and-postflip.md), and the move to
`trialComplete` waits for `stimOff > 0`. `trialRunDone` is strobed when the run loop
exits, and `trialEnd` is strobed in `_finish` after the parameter strobes. Post-trial
waits (`postRewardDuration` or `timeoutAfterFixBreak`, then `iti`) run in
`postTrialTimeOut`.

## Conditions / trial structure

There is no trial array. `barsweep_init.m` sets `p.init.barsweepSchedule.angleList` from
`exptType`. `p.status.barsweepPool` holds a shuffled order: `shuffleAngleList` with
`barsweepPairShuffle = true` draws each (θ, θ+180) pair together. `nextParams.m` only
*peeks* at `pool(1)`. `barsweep_finish.m` is the only place the pool changes: on a
rewarded (`trialComplete`) trial it pops the front (fixBreak and nonStart leave the pool unchanged), and when the pool is empty it increments
`barsweepSetsCompleted` and reshuffles. `setRepeats` (default 50 rewarded sweeps per
angle) is frozen on the first `_next` call. Once `barsweepSetsCompleted` reaches it,
`_next` sets `barsweepSessionDone`, `_run` returns at once, and `_finish` stops the Run
button.

Geometry: `nextParams.m` works out both sweep endpoints as absolute dva positions first
and converts each to pixels with `pds.deg2pix` (a tangent mapping). Per-frame positions
are interpolated in degrees and converted frame by frame, so `speedDegPerSec` is a true
angular speed. Sessions recorded with this geometry carry `sweepGeometryVersion = 2`.
Bar textures for the whole sweep are built in `_next` and released in `_finish`.

## Key trVars and settings

`pathCenterXDeg = -17`, `pathCenterYDeg = 0`, `pathLengthDeg = 40`, `speedDegPerSec = 20`,
`barWidthDeg = 1`, `barLengthDeg = 80`, `stimulusMode = 2` (1 = luminance noise bar with
`noiseCheckSizeDeg = 0.25`, 2 = solid). Luminance palette indices are
`backgroundLumIdx`, `barLumIdx`, `noiseLumLowIdx` and `noiseLumHighIdx` into black / bg /
white. Online-RF knobs: `useOnlineRF = true`, `rfNChannels = 64`, `rfLatencyMs = 40`,
`rfPosBinDeg = 0.25`, `rfMapExtentDeg = 10`, `rfRampFilter = 'Hann'`,
`rfRampCutoff = 0.5` (the last two apply to rfmap12 only), and `rfDetectThresh = 4`
(peak/noise-MAD SNR). `connectRipple = 1`. Changing a spatial knob mid-session (path
length, bar width, position bin, or a path-center move larger than one bin) saves the
accumulator to `<sessionId>_barsweepRF_reset<N>.mat` and starts a fresh one.
Reconstruction-only knobs are read live and never trigger a reset (local
`barsweepRF_detectAndReset` in `barsweep_finish.m`).

## Online RF

`initBarsweepRF` → `accumulateBarsweepRF` (per trial; fixBreak trials contribute up to
the break, nonStart trials are skipped) → `reconstructBarsweepRF` → `plotBarsweepRF` plus
a per-channel browser (`initBarsweepChannelBrowser` / `updateBarsweepChannelBrowser`). In
accumulator format version 2, cardinal4 stores its accumulator **by direction** (4 rows)
with no assumed-latency subtraction, because the midpoint of opposite peaks cancels
latency. rfmap12 stays orientation-keyed and subtracts `rfLatencyMs`. The GUI action
`pdsActions.exportBarsweepRFCentersCSV` writes `channel,x_deg,y_deg,snr,latency_ms` CSVs
(the first three columns match rfMap's export), for use by
[sacc_to_phosph](sacc_to_phosph.md). Offline helpers: `testBarsweepRF` (synthetic
spikes, both regimes), `validateBarsweepSession`, `auditBarsweepStrobes`,
`decodeRippleEvents`, `rebuildBarsweepRFFromTrials`, `replayBarsweepRF`.

## Data & strobes

Per-trial files (`pds.saveP`) carry `trData` with timing, the trimmed spikes and events,
and sweep fields (`pathAngleDeg`, `sweepCenterDeg`, `sweepStartPix`/`EndPix`,
`sweepFrames`, nominal/visible/motion durations, `speedDegPerSec_realized`,
`barsweepPoolAtTrialStart`). The large `spikeHist`/`dwellTime` arrays are removed from
`p.init.barsweepRF` before `saveP`. The full accumulator is overwritten each trial in the
sidecar `<sessionId>_barsweepRF.mat`, the only on-disk copy, which the CSV export reads
after a session. `p.status` is appended to `p.mat` on every trial, nonStarts included.
The strobeList (generated block) uses polar coordinates for the path center and fixation
(`_x10` + 1800 for angles, `_x100` for radii). Task code: `uniqueTaskCode_barsweep`
(32022). There is no data dictionary. The strobe round-trip checks are in
`analysisPlanningDocs/barsweep_pre_recording_validation_plan.md`.

## Session practice & decisions

- The geometry report (`analysisPlanningDocs/barsweep_geometry_discrepancy_report.md`,
  2026-08-17) records that collaborators recording right LGN ran cardinal4 with
  `pathCenterXDeg = -17`, `pathLengthDeg = 40`. Before cb4170fd, that setup started
  leftward sweeps at +6.5° instead of +3.0° and spanned 42.44°. For data collected
  earlier, `barsweepSweepAxisToDeg` relabels the old sweep axis exactly, and
  `correctBarsweepRFCenters` writes raw and corrected centers side by side (re-accumulating
  pre-v2 sidecars from `trial####.mat`).
- The cardinal4 regime assumes RF separability. The online-mapping plan considers this
  reasonable for LGN and most SC cells, not for oriented V1 cells
  (`analysisPlanningDocs/barsweep_online_rf_mapping_plan.md`).

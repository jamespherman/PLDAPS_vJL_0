# conflict_task

conflict_task pits goal-directed control (reward expectation) against stimulus-driven control
(salience) in a compelled-saccade design. The subject holds the joystick and fixates; two
bullseye targets, one on each side, differ only in hue contrast with the background. After a
variable hold the fixation point goes off (go signal) and the subject saccades to either
target. Both choices are rewarded, but the reward size depends on the chosen **side**, and the
side that pays more changes across three phases. Target onset is shifted relative to the go
signal (`deltaT`), so the tachometric relation between processing time and choice can show when
salience versus reward controls the saccade. The implementation plan
(`analysisPlanningDocs/conflict_task_implementation_plan.md`) names gSac_4factors as the base
task.

## Trial flow

`trialBegun` → `waitForJoy` (press within `joyWaitDur`) → `showFix` (acquire within
`fixWaitDur` while holding the joystick) → `dontMove` (hold for `timeGoSignal`, uniform
`fixHoldDurationMin`–`Max` = 1.0–1.2 s) → `makeSaccade` (fixation off; saccade must start within
`responseWindow`, 0.45 s) → `checkLanding` → `holdTarg` (`targHoldDuration`, 0.2–0.3 s) →
`sacComplete` (reward). Errors end in `fixBreak`, `joyBreak`, `nonStart`, `noResponse` or
`inaccurate` (landing outside both 5° target windows, including the empty location on a
single-target trial), and `p.trData.outcomeCode` codes each (1 high salience, 2 low salience,
3–7 errors). Target onset is driven separately by `timingMachine`: both targets appear together
at `timeStimOnset = timeGoSignal + deltaT` after fixation acquisition. `fixOn`, `fixOff` and
`stimOn` use the postFlip mechanism, and `makeSaccade` waits for `timing.fixOff > 0` before
timing the response window (the pattern described in [CLAUDE.md](../../CLAUDE.md)).

`passJoy` defaults to 1, so the joystick checks pass unless it is set to 0.

## Conditions / trial structure

`initTrialStructure` builds the whole session at init: 448 rows in three phases.

- **Dual-target conditions, 128 per phase:** 4 left locations (135°, 165°, −165°, −135°) × 4 right
  locations (45°, 15°, −15°, −45°), all at `targetEccentricityDeg` = 10°; × 2 background hues;
  × 2 high-salience sides; × 2 `deltaT` values (0 and +125 ms).
- **Phase 1** adds 64 single-target trials that show only the high-salience target (32 left, 32
  right). `chooseRow` draws only single-target rows until all are done, then the 128 dual rows.
  Reward ratio is 1:1 in Phase 1 regardless of `rewardRatioBig`.
- **Phase 2:** big reward on the right on `rewardProbHigh` (0.85) of trials, left on the rest.
- **Phase 3:** big reward on the left on 0.85 of trials.

`rewardBigSide` is stored per row. `calculateRewards` splits a fixed budget `rewardDurationMs`
(C = 400 ms) between the sides in the ratio `rewardRatioBig`:1 (1.5:1), giving
`rewardDurationLeft`/`Right`. A trial is "conflict" when `rewardBigSide ≠ highSalienceSide`.
Rows are drawn at random within the current phase; `updateTrialsList` marks a row done only on
a completed choice, so errors are re-drawn later. When every row is done, `nextParams` prints
that the session is complete and sets `exitWhileLoop`.

**Salience.** `setBackgroundColor` follows the rule in CLAUDE.md ("Conflict Task: Salience via
DKL Color Contrast"): background DKL 0° gives a 180° high-salience target and a 45° low-salience
target; background 180° gives 0° and 225°. Each target is drawn with its own hue
(`leftTargHueIdx`, `rightTargHueIdx`), assigned from `highSalienceSide` (1 = left, 2 = right).

## Key trVars

GUI quick-access variables include `targetEccentricityDeg`, `rewardDurationMs`, window sizes,
`responseWindow`, `fixHoldDurationMin/Max` and the reward-ratio fields. There is one settings
file. `timeoutAfterFa` (1 s) and `timeoutSacErr` (2 s) set the post-error timeouts.

## Data & strobes

Per trial, `p.trData` holds `chosenSide` (1 left, 2 right, 0 none), `choseHighSalience`,
`outcome`/`outcomeCode`, the timing fields, and offline saccade parameters from
`calcSacParams` in `_finish` (`SRT` = saccade onset − `fixOff`, `processingTime` = SRT +
`deltaT`, `peakVel`, pre/post-saccade positions). With `passEye`, `calcSacParams` fills these
with simulated values. Ripple data are pulled each trial when Ripple is connected.

`p.init.taskCode` is set by `pds.initTaskMetadata` in the settings file (32016). Notable
strobeList rows: `deltaT` is sent as `deltaT + 1000`, and target locations are sent as polar
`leftTargTheta`/`rightTargTheta` (angle ×10 + 1800) with radius ×100, following the conventions
in CLAUDE.md. `hueType` carries `backgroundHueIdx`, and `highRewardLocation` carries the
per-trial `rewardBigSide`. Codes 16021–16024 and 16029 are shared with SRS_Task_Smooth, which uses the
opposite side convention (see the [family page](family-srs.md)).

There is no data dictionary. supportFunctions holds per-session analysis scripts
(`analyzeConflictSessions`, `analyzeFeb16Session` … `analyzeFeb25Session`, `analyzeRPT`,
`plotConflictTaskSession`) and design notes: `REFACTOR_PLAN.md` / `CONFLICT_TASK_REFACTOR_PLAN.md`,
`SINGLE_STIM_IMPLEMENTATION_PLAN.md`, `MULTI_SESSION_ANALYSIS_PLAN.md` (Feb 2026 sessions) and
`target_timing_report.md`. These record earlier designs (for example ±150 ms `deltaT`, 2:1
ratio), so check them against the current code.

## Session practice & decisions

- Commit 1215a7e7 (2026-04-29) retuned the task "from recent sessions": `deltaT` [−150, 150] →
  [0, 125] ms, `rewardRatioBig` 2.0 → 1.5, `rewardProbHigh` 0.9 → 0.85, response window 0.6 →
  0.45 s. It also made Phase 1 a pure-salience baseline (ratio 1:1).
- `SINGLE_STIM_IMPLEMENTATION_PLAN.md` gives the reason for the Phase 1 single-target trials:
  the monkey had a rightward spatial bias, and left-only trials force leftward saccades.

# rfMap

The subject holds fixation on a central point while a pre-generated stimulus plays across
the screen (or one hemifield). Spikes are read from Ripple after each trial and
reverse-correlated with the stimulus, so the experimenter watches per-channel
receptive-field (RF) maps build up during the session. The output is used to place
stimuli and pick electrodes for downstream tasks, most directly
[sacc_to_phosph](sacc_to_phosph.md). One settings file selects one of four **stim types**,
and each session uses exactly one:

| `p.init.stimType` | Settings file | Online output |
|---|---|---|
| `denseAchromatic` | `rfMap_denseAchromatic_settings.m` | spatial STA `[nY, nX, nLags]` per channel |
| `denseChromatic` | `rfMap_denseChromatic_settings.m` | DKL STA `[nY, nX, 3, nLags]` (axes L−M, S, achromatic) |
| `sparse` | `rfMap_sparseBalanced_settings.m` | spatial STA (N/2 white + N/2 black spots per frame) |
| `checkerboard` | `rfMap_checkerboard_settings.m` | per-(channel, checkSize, contrast) temporal kernel + F1/F2. **No spatial RF.** |

All four call `rfMap_commonSettings.m` after setting `p.init.stimType`. That file holds
the shared states, trial variables, trData list and base strobeList, and it maps the
string to an integer (1–4) for strobing. Per-type files only add overrides and extra
strobe rows. Session IDs end in the stim type (`..._rfMap_denseChromatic`).

## Trial flow

States (from `rfMap_commonSettings.m`; see the generated facts below):
`trialBegun → showFix → holdFixAndPlay → noiseComplete` (rewarded), with aborts to
`fixBreak` (gaze leaves the window during the stimulus; low tone) or `nonStart` (no
fixation within `fixWaitDur`). In `holdFixAndPlay`, `rfMap_run.m` picks the noise frame
from time since `stimOn` (`floor(displayFrames / noiseFrameHold) + 1`). When the trial's
frames run out, the stimulus and fixation point are removed. `stimOff` and `fixOff` are
tagged via [postFlip](../concepts/drawing-and-postflip.md), and the transition to
`noiseComplete` waits for `stimOff > 0`, so the reward strobe always follows the
`stimOff` strobe. A background-colored clearing patch (`clearPatchDeg`, disk or square)
is drawn over fixation on top of the noise. Checkerboard trials queue
`rfMapCheckReversalEvent` plus the new polarity (1 = +, 2 = −) at each polarity flip.
`trialRunDone` is strobed when the run loop exits, and `trialEnd` is strobed in
`rfMap_finish.m` after the paired info strobes.

## Conditions / trial structure

`supportFunctions/initTrialStructure.m` builds the trial array in one of two ways:

- **Noise-movie modes** (dense achromatic, dense chromatic, sparse): one movie of
  `movieDurationMin` (default 10 min) at the noise update rate is played in order, and
  each trial takes the next `trialDurationS` chunk of it. The trial array is just
  `trialIndex`. For `denseChromatic` it also has a `chromaticSeed` column, drawn from the
  master `noiseRngSeed`. Aborted trials replay the same frame range. When the cursor runs
  past the end, `nextParams.m` wraps it and increments `p.init.noiseCycleCount`.
- **Checkerboard:** a seeded permutation of `checkRepsPerCondition` copies of every
  (`checkSizesDva` × `checkContrasts`) pair. Columns are `trialIndex, checkSizeIdx,
  contrastIdx, completed`. A row is popped only on success, so aborted rows are retried.

The session stops on its own (`rfMapSessionComplete.m`, checked at the top of `_next` and
`_finish`, which then calls `pds.stopRunButton`). Checkerboard stops when its trial array
is used up. The STA modes stop after `targetNoiseCycles` (default 1) full passes of the
movie.

Stimulus generation happens in `rfMap_init.m` (local `generateStimForTask`).
`denseAchromatic` and `sparse` pre-render the whole movie into `p.init.noiseMovie`.
`denseChromatic` regenerates each trial's movie and DKL drive tensor in `nextParams.m`
from that trial's seed: a whole-session tensor at LGN grid sizes would be about 8.6 GB.
This scheme is `sessionFormatVersion = 2`. Checkerboard pre-renders one texture per
(size, contrast, polarity) and keeps them on the GPU. `noiseFrameHold` is derived at
init as `round(refreshRate / noiseTargetUpdateHz)`. The common rate is 12 Hz, chromatic
uses 10 Hz, and checkerboard pins `noiseFrameHold = 1`.

## Key trVars and settings variants

- Common defaults: `checkSizeDeg = 2`, `nChannels = 64`, `nSTALags = 8`,
  `trialDurationS = 1.5`, `fixWinWidthDeg/HeightDeg = 2`, `rewardDurationMs = 160`,
  `connectRipple = 1`, `noiseRngSeed = 12345`, and `stimHemifield = 'full'` (`'left'` or
  `'right'` halves the grid; the comment notes that right LGN recordings use `'left'`).
- `denseChromatic`: `dklAxes = [1 2 3]` (tri-noise, 8 corner states per check),
  `dklContrasts = 0.45` (from `gamutMaxContrasts`, 0.4738 for the shipped rig LUTs, minus
  a 5% margin), and `dklCalibrationSource = 'measured_primaries+measured_gamma'`. The
  reasons for using DKL rather than RGB axes are in `tasks/rfMap/dklVsRgbChomaticNoise.md`.
- `sparse`: `nSparseSpots = 6`, `sparseBalancedFlag = 2` (balanced TwinDeck; 1 = legacy
  uniform-random).
- `checkerboard`: `checkSizesDva = [0.5 1.0]`, `checkContrasts = 1.0`,
  `checkReversalHz = 5` (flip rate, so F1 = 2.5 Hz), `checkRepsPerCondition = 20`,
  `trialDurationS = 2`, `nSTALags = 24`.
- **Simulation wrappers** `rfMap_sim_<type>_settings.m`: each calls the real settings file,
  then sets `passEye = 1`, `useSimulatedSpikes = true`, `connectRipple = 0` and
  `stimHemifield = 'left'`. If `simPopulations/lgn_population_042.mat` exists, it is set
  as `simPopulationFile`. `sim_setup_population.m` creates that file once with
  `simGeneratePopulation` (12 neurons, 64 channels, left hemifield, seed 42). In sim mode
  `rfMap_init.m` builds a kernel bank (`simLoadPopulation` or `simInitKernelBank`), and
  `rfMap_finish.m` calls `simulateRippleData` (LNP spikes) instead of
  `pds.getRippleData`. Design: `_validation/SIM_MODE_PLAN.md`.

## Online RF estimation and tools

- **Spike handling (`rfMap_finish.m`):** spikes outside `[stimOn, stimOn + trial
  duration]` on the Ripple clock are discarded before saving. On good trials,
  `accumulateSTA` dispatches to `updateSTA` (spatial modes) or `updateSTA_checkerboard`.
  Spatial accumulators then have the fixation-occluded checks zeroed
  (`occludedCheckMask` / `applyOccludedMask`). Plots refresh every
  `staPlotEveryNTrials` (5) good trials.
- **RF centers:** `computeRFCenters.m` finds the peak-energy lag, thresholds `|slice|` at
  `rfCenterThreshFrac` (0.5) × max, and takes the centroid. The result is in dva relative
  to fixation, saved on every trial as `p.trData.rfCentersDeg` (`nChannels × 2`, the last
  valid estimate carried forward). It is all-NaN for checkerboard.
- **Browsers:** the STA figure (`initSTADisplay*`, `plotSTA*`) and a per-channel
  `uifigure` browser (`initSTAChannelBrowser` / `updateSTAChannelBrowser` with
  RF-center markers and a PDF save button; `initCheckerboardChannelBrowser` /
  `updateCheckerboardChannelBrowser` show an F1-amplitude grid). See
  `analysisPlanningDocs/rf_browser_ux_improvements_plan.md`.
- **GUI actions** (in `+pdsActions`, see [pdsActions](../library/pdsActions.md)):
  `exportRFCentersCSV` writes `channel,x_deg,y_deg`, either in session or from the latest
  `trial*.mat` of a folder you choose; its header says sacc_to_phosph consumes the file
  manually. `evaluateRFQuality` runs `computeChannelQuality` (spike count, peak SNR,
  spatial SNR, spread → `passGo`) and, in sim mode, compares results to ground truth.
  `recheckThresholds` runs `pds.recheckSpikeThresholds`. Spike thresholds are set from
  RMS at init (`pds.setSpikeThreshFromRMS`), and drift is tracked passively each good
  trial (`pds.monitorSpikeThresholds`).
- **`_validation/`**: offline scripts (`test_*`, `check_*`, `convergence_test`,
  `evaluateSimSession`, `auditSession` = post-session integrity audit,
  `reanalyze_real_session`, …), result figures (`figs_*`), `_legacy_snapshot/` (frozen
  pre-merge generator and STA code), and two plan docs: `SIM_MODE_PLAN.md` and
  `PLAN_rf_estimation_pipeline.md`.

## Data & strobes

`pds.saveP` writes `p.init` with every trial. `rfMap_finish.m` removes `noiseMovie`,
`staAccum` and the figure handles before saving and restores them afterwards, so the
movie is **not** on disk. It is rebuilt from the seed and generator parameters (recipe in
the data dictionary). Per-trial `trData` includes eye/joystick traces, the trimmed
`spikeTimes`/`spikeClusters`, Ripple `eventTimes`/`eventValues`, timing (`fixOn`,
`fixAq`, `stimOn`, `stimOff`, `fixOff`, `fixBreak`, `reward`, `trialRunDone`,
`trialEnd`, …), `rfCentersDeg` and `strobed`.

The base strobeList (in the generated block, from the primary settings file) sends
stim type, format version, check size, frame hold, RNG seed (low and high 15-bit halves),
the trial's frame range, total frames, grid size, noise cycle count and hemifield. Per-type
additions: chromatic (`rfMapDklAxisIdx`, `rfMapDklContrast_x100`, `rfMapDklCalibSource`),
sparse (`noiseNSparseSpots`, `rfMapSparseBalancedFlag`) and checkerboard
(`rfMapCheckSizeIdx`, `rfMapCheckContrastIdx`, `rfMapCheckReversalHz_x10`). rfMap sets
`p.init.taskCode = 32020` (= `uniqueTaskCode_rfMap`) in `rfMap_init.m`. Codes
16140–16159 are documented in `data_dictionaries/rfMap_data_dictionary.md`; its table
still lists 16160–16175 as reserved and predates `rfMapNoiseCycleCount` (16160) and
`rfMapStimHemifield` (16161), which are defined in `+pds/initCodes.m`. See also [strobe codes](../concepts/strobe-codes.md) and
the [registry](../reference/strobe-codes.md).

## Session practice & decisions

- `_validation/PLAN_rf_estimation_pipeline.md` (2026-06-02/03) records a recommended
  session sequence: a short checkerboard run to pre-screen responsive channels, then
  denseAchromatic at 2.0 dva in the contralateral hemifield (right LGN → left) for about
  400–500 trials. In simulation, about 500 trials recovered most RF channels at a median
  center error of about 0.4 checks. The same doc lists real-session spike rates from a
  64-channel right-LGN probe (2026-06-01).
- The checkerboard is a cell-characterization mode (magno/parvo typing via
  F1/(F1+F2)), not a spatial map. Check size is a spatial-scale knob, not a clean
  spatial-frequency manipulation (`rfMap_checkerboard_settings.m`, merge plan).
- The merge plan explicitly leaves out jitter and apertures. They were cancelled, and
  codes 16151–16157 stay reserved and unused
  (`analysisPlanningDocs/rfMap_unified_merge_plan.md`).

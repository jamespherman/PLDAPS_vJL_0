# seansFirstTask

A numerosity discrimination task. The subject holds the joystick and fixates; a stimulus made of
one or two small shapes (ovals, rectangles, or one of each) flashes at a random location; then
the target(s) appear and the fixation point goes off. The subject must saccade to **target 1**
(a single dot) if the stimulus had one element, or to **target 2** (a pair of dots) if it had
two. A correct choice is rewarded; a saccade to the
other target ends the trial in `wrongTarget`. Analysis notes:
`analysisPlanningDocs/seansFirstTask_analysis_planning.md`.

[numerosity](numerosity.md) started as a copy of this task (commit 9c0aa4cc).

## Trial flow

`trialBegun` → `waitForJoy` → `showFix` → `dontMove` (stimulus, then targets, appear while
fixation is held; fixation goes off at `timeFixOffset`) → `makeSaccade` (leave fixation between
`goLatencyMin` and `goLatencyMax`, 0.1–0.5 s) → `checkLanding` → `holdTarg`
(`targHoldDuration`, 0.3–0.5 s) → `sacComplete` (reward `rewardDurationMs`, 180 ms). Landing
in target 1 or 2 within `maxSacDurationToAccept` (0.1 s) strobes `saccToTargetOne` or
`saccToTargetTwo`; landing in the wrong one sets `p.trData.wrongTargetFlag` and ends in
`wrongTarget`. Joystick release ends in `joyBreak`, eye errors in `fixBreak`. The joystick checks
pass unless `passJoy` (default 1) is set to 0. `fixBreak`, `joyBreak`, `nonStart` and
`wrongTarget` play the low tone.

Event timing, all measured from fixation acquisition (`timingInfo` in `nextParams`):
stimulus element 1 onset `stimOnsetMin`–`Max` (0.25–0.4 s) for `stimDurMin`–`Max`
(0.12–0.20 s); element 2 timing set by `temporalOverlap` (below); targets
`targOnsetMin`–`Max` (0.15–0.2 s) after the stimulus ends; go signal
`goTimePostTargMin`–`Max` (0.25–0.4 s) after target onset.

## Conditions / trial structure

`initTrialStructure` (experiment type `step1`) builds rows of
`numDots × numTargets × targsSameColor × stimShape` with repetition counts and trial codes
24001–24017. Only five rows currently have non-zero repetitions, all with two targets of
different colors: one element oval (24004, 5 reps), two elements oval (24008, 3), one element
rectangle (24012, 5), two elements rectangle (24016, 3), and two elements oval + rectangle
(24017, 4). `chooseRow` picks a random remaining row; `updateTrialsList` removes a row only after
a good trial and refills the block when it is empty. Row selection runs because the default target
preset `preset_quatro` sets `setTargLocViaTrialArray = true`.

Each trial, `nextParams` also randomizes the stimulus: location within
`stimRangeX/Ymin`–`max`, element sizes (`stimSizeMin`–`Max`), rotations, separation
(`twoStimSepDegMin`–`Max`), and colors (random RGB, avoiding background gray; element 2 matches
element 1 half the time). It builds the stimulus textures and pushes stimulus color ramps into
CLUT rows 51–250.

**`temporalOverlap`** (default 0) controls how the two stimulus elements are timed:

| `temporalOverlap` | Presentation |
|---|---|
| 0 | temporal: element 2 follows element 1 after `interStimIntervalMin`–`Max` (0.03–0.12 s) |
| between 0 and 1 | transition: element 2 starts partway through element 1 |
| ≥ 1 | spatial: both elements on and off together |

CLUT row 5 is set to green when `temporalOverlap < 1` and red otherwise.

## Data & strobes

`p.trData.trialEndState` is the main outcome (21 correct, 22 wrong target, 31–34 aborts), with
`wrongTargetFlag` and `timing.*` (saccade onset/offset for SRT). Trial-level stimulus parameters
(`numDots`, `numTargets`, `stimShape`, positions, colors, timing) are in `p.trVars`. The strobeList
(generated above) sends `taskCode` (32013, set by `pds.initTaskMetadata` in the settings file),
date/time, target polar coordinates, reward duration, trial counts and the row's `trialCode`.
Visual events (`stimOn`/`stimOff`, `targetOn`, `fixOn`/`fixOff`) are strobed through the
flip-locked path; behavioral events through `strobeNow`.

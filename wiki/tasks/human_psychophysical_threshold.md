# human_psychophysical_threshold

A threshold task for **human** subjects (`p.init.subjType = 'Human'`). It does not use the
DataPixx (`useDataPixxBool = false`): gaze comes from an Eyelink and responses from a
keyboard. On each trial four patches appear at 45°, 135°, 225° and 315° around fixation
(`stimLoc1Elev` + [0 90 180 270]). During a central "target" interval, one patch (the
oddball) differs from the other three in a single feature: hue, orientation, drift speed,
or radial-frequency shape. The subject keeps fixating and then presses the numeric-keypad
key at the oddball's position (9, 7, 1, 3 for locations 1–4). QUEST adjusts the signal
strength to estimate the 75%-correct threshold (guess rate 0.25). Once the estimate
stabilizes, 20 trials are run at a fixed signal strength to validate it, and then the
session ends by itself.

## Trial flow

States are in the generated block. Only `trialBegun`, `showFix`, `dontMove`,
`makeDecision`, `trialCompleted`, `fixBreak` and `nonStart` are used. The other state names
come from [scd](scd.md).

1. **`trialBegun`**: draws the stimulus and fixation boxes on the Eyelink host display.
   Practice trials are marked with an Eyelink message `PRCTCTR`.
2. **`showFix`**: fixation point on. Fixation must be acquired within `fixWaitDur`
   (`pds.eyeInWindowEL`), otherwise the trial ends as `nonStart`.
3. **`dontMove`**: the stimuli run for a pre-mask interval, then a `targetItvlDur` (1.5 s)
   target interval, then a post-mask interval. Each mask lasts
   `maskItvlMin + rand*maskItvlWin`. What the masks scramble depends on the feature:
   - hue experiments randomize hue and saturation (`hueMaskVar`, `satMask`, `satMaskVar`);
   - orientation and speed experiments apply `orientMaskVar`, `ctrstMask` and
     `lumMaskVar`, and the speed masks keep each patch's target-interval speed. The keyboard queue starts at stimulus onset.
4. **`makeDecision`**: after stimulus offset the fixation point turns blue and the task
   waits for the first keypress (`KbQueueCheck`). `passJoy` simulates a random response.
5. **End**: a fixation break at any point during the stimulus gives `fixBreak`.

Event times use the postFlip mechanism. Each postFlip entry also sends a matching Eyelink
message (`FIX_ON`, `STIM_ON`, `STIM_OFF`), along with `FIX_ACQ`, `FIX_BREAK`, `RSP_<key>`
and `TRIAL_END`.

## Conditions / trial structure

`initTrialStructure` uses scd's trials-array layout extended to four stimulus locations.
Each table has four rows, one per oddball location (`stim chg` 1–4), with 10 repetitions
each and trialCodes 23901–23904. The feature flag set in a row picks the experiment:

- `hue` for `human_psychophysics_hue_discrimination`;
- `orientation` for `human_psychophysics_orientation_discrimination`;
- `speed` for `human_psychophysics_speed_discrimination`. If the settings file name ends
  in `2`, the speed flag is negated, so the oddball moves slower instead of faster;
- `spatial frequency` for `human_psychophysics_rfFreq_discrimination` (radial-frequency
  gratings, `rfFlag = true`).

The hue arrays are duplicated, giving 80 trials per block.

In `nextParams`, the oddball's feature delta is set as follows:

- **Practice trials** (`practiceTrials`, a GUI toggle): `supraSignalStrength`. QUEST is
  not updated.
- **Otherwise**: `signalStrength` from `getQuestSuggestedDelta`. That function uses the
  QUEST quantile clipped to [`minSignalStrength`, `maxSignalStrength`], except that 10% of
  trials use `supraSignalStrength` and 20% use a zero signal.

After 25 or more QUEST trials, `_finish` checks how much the 95% CI width of the threshold
estimate changed from trial to trial. Once the change stays below
`grain / divFactorNoThreshChg` for `numThreshCheckTrials` trials, `fixSignalStrength`
switches on and the current threshold estimate becomes the fixed signal. After 20 good
fixed-signal trials, `_finish` closes the EDF file and transfers it to `output/`
(`transferEdfFile`), stops the run loop (`p.runFlag = false`), and saves two figures:
`<edfFile>_<date>_summaryFig.fig` (threshold trace and percent correct with binomial CI)
and `_tChgFig.fig` (CI-change trace).

## Key trVars and settings variants

| Settings file | Experiment | Notable values |
|---|---|---|
| `_hue1` … `_hue4` | hue | `hueInit` 0 / 90 / 180 / 270, `satInit` 0.4, `hueDelta` 45, 6° eccentricity |
| `_orientation` | orientation | `ctrstInit` 0.2, `satInit` 0, QUEST guess 45, max signal 90 |
| `_speed1`, `_speed2` | speed (faster / slower oddball) | `speedInit` π/6. `_init` recomputes min/mid/max speed and the QUEST range from `freqInit` for any settings file containing "speed" |
| `_radFreq` | radial frequency | `rfFlag` true, `freqDelta` 1, 10° eccentricity, `useQuest` false |
| `human_psychophysical_threshold_settings.m` | hue (older base file) | 10° eccentricity, `hueInit` 180, fixation-dimming values, reward actions |

`_hue2`–`_hue4`, `_orientation` and the speed files choose `rigConfig_human_Mercy` on the
host `mayolab-thinkpad-p16s-gen-2` and `rigConfig_human` on any other host. The rest always
use `rigConfig_human`. `makeKbQueue` looks for a "Dell KB216 Wired Keyboard" and asks for a
device if it does not find one. The task actions include `i1CalibrateAndMeasure`,
`i1Validate` and `dklToRgbFileMaker` for photometer-based color calibration
([color and calibration](../concepts/color-and-calibration.md)).

## Data & strobes

No strobes are sent (the strobeList holds only the date and time, and `_finish` does not
call `pds.strobeTrialData`). Event markers go to the Eyelink EDF file as messages instead
(see Trial flow). Each trial saves `p.trData.responseValue`, `p.trData.timing.responseTime`,
`p.trData.responseCorrect` (`[9 7 1 3]` mapped onto `stimChgIdx`) and the timing fields.
`p.init.questObj` holds the QUEST history (`threshEst`, `threshEstCi`,
`fixedSignalStrength`). Correct and wrong answers get different feedback tones (`sound`).
There is no data dictionary.

The repo-root `Psycho/` folder holds MATLAB figures named `<ID>_<date>_Psycho.fig` and
`_PsychoConfusion.fig` (dated 5-24-24 and 5-31-24), added in commits e3e53b50 and ac709aa8.
No code in this task writes files with those names.

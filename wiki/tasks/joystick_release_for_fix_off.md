# joystick_release_for_fix_off

This task introduces **releasing** the joystick as the response. The settings header
describes it: "On some proportion of trials, the fixation point turns off without reward
delivery or 'boop', monkey must release joystick to get reward on those trials. On the
remaining trials, the 'boop' and reward are delivered simultaneously with fixation
offset."

## Trial flow

`waitForJoy` → `showFix` → `dontMove` work as in
[joystick_press_and_fixate](joystick_press_and_fixate.md). The difference comes when
`fixDurReq` is met:

- If `isRelOnFixOffTrial` is true, the fixation point is set to background and the trial
  goes to `makeDecision`. A release (or `passJoy`) strobes `hit` and plays the high tone.
  If there is no release within `maxJoyRelLatency` (10 s), the trial ends as `miss`.
- Otherwise the run strobes `hit` and plays the high tone at once, as in the parent.

In `hit`, reward follows `rewardDelay` after `fixHoldReqMet`. `fixBreak`, `joyBreak` and
`nonStart` work as in the parent.

## Conditions

`nextParams` → `trialTypeInfo` sets `isRelOnFixOffTrial = rand < propRelTrials`
(default 0.2). `locationInfo` jitters the fixation point (`fixLocRandX/Y`).
`timingInfo` draws `fixDurReq`. There is no trials array.

## Key trVars

The GUI shows `propRelTrials`, `maxJoyRelLatency`, `fixWinWidthDeg/HeightDeg`, `fixDegX/Y`,
`fixDurReqMin/Max`, `rewardDelay` and `rewardDurationMs`. The CLUT adds four grey levels
(`expWhite20…80`), which this task's run does not use.

## Data & strobes

- Timing: `joyPress`, `fixOn`, `fixAq`, `fixHoldReqMet`, `fixBreak`, `joyRelease`,
  `reward`. `p.trVars.isRelOnFixOffTrial` identifies the trial type.
- `updateStatusVariables` appends each trial's end state to `p.status.trialEndStates`.
- strobeList: date and time only.
